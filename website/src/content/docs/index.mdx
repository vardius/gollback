## What you get

<CardGrid>
	<Card title="Typed results" icon="approve-check">
		An `AsyncFunc[T]` returns a `T`, so `Race` and `Retry` return one and `All` returns a `[]T`. No
		`interface{}`, no type assertions.
	</Card>
	<Card title="Cancellation built in" icon="close">
		Every function gets a context. The moment one wins a race, the others' context is cancelled, so
		their requests stop.
	</Card>
	<Card title="Every error kept" icon="warning">
		When every racer fails, you get all their errors joined. `All` returns each function's error in its
		place.
	</Card>
	<Card title="Lean" icon="rocket">
		`Retry` allocates nothing, `All` runs the first function on your goroutine, and tests count every
		allocation.
	</Card>
	<Card title="Deterministic tests" icon="check">
		Tested on a fake clock with `testing/synctest`: exact timings, no sleeps, 100% coverage.
	</Card>
	<Card title="Small API" icon="puzzle">
		Three functions and one type. Nothing to configure and no dependencies beyond the standard library.
	</Card>
</CardGrid>

## Faster than v1, with a third of the allocations

<p class="landing-lead">
	v2 starts one goroutine per function and nothing else, keeps results in one place instead of passing them
	through channels, and never allocates to retry. Racing one function went from 795 ns to 349 ns.
</p>

## Coming from v1

<p class="landing-lead">
	The functions are the same. They are generic now, so the type assertions go, and a few edge cases changed:
	all errors when every racer fails, and no results beside errors.
</p>

<div class="compare">

```go title="v1"
res, err := gollback.Race(ctx,
	func(ctx context.Context) (interface{}, error) {
		return primary.User(ctx, id)
	},
	func(ctx context.Context) (interface{}, error) {
		return replica.User(ctx, id)
	},
)
user := res.(User)
```

```go title="v2"
user, err := gollback.Race(ctx,
	func(ctx context.Context) (User, error) {
		return primary.User(ctx, id)
	},
	func(ctx context.Context) (User, error) {
		return replica.User(ctx, id)
	},
)
```
